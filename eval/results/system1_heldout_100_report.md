# System-1 held-out evaluation: 100-task trace analysis

**Run:** [`batch_heldout_100_system1/summary.json`](heldout/batch_heldout_100_system1/summary.json) and its 100 task JSON trajectories, 100 SQLite snapshots, and 19 generated patches. **Controller:** CPU `bob-s1-0.8b`, `go-probe-sanitized-v1`, hybrid loop guard, `fallback_on_error=false`; the task-solving model remained `Qwen3.6-35B-A3B-MTP-GGUF`. **Comparator:** [published baseline report](baseline_100_report.md), plus [`heldout_100`](heldout/heldout_100/summary.json), [`timeouts_44`](heldout/timeouts_44/summary.json), [`swe_iterations_17`](heldout/swe_iterations_17/summary.json), and the [eight-patch Docker regrade](heldout/baseline_pending_8_docker_regrade.json). Analysis performed 2026-11-21.

## Executive assessment

The new run resolved **56/100** tasks, one more than the published **55/100** baseline. After applying the fresh Docker grades to baseline patches and using the same per-task grading convention, the merged baseline is **58/100**: System-1 is **two tasks lower**. The 98 gradable tasks give **56/98 (57.1%)** versus **58/98 (59.2%)**. Two Bash query tasks have an empty oracle in both runs; neither can establish success. The run has useful long-horizon compaction and no sidecar fallback, but the compaction classifier never skips a probe, the loop classifier rarely intervenes, and its one intervention ends a solvable CTF attempt. These are associations in two stochastic runs, not a controlled causal estimate of the controller's effect.

## What the controller did well

**Calibrated, reliable sidecar calls.** All **226/226** compaction-gate decisions report `calibration_applied=true`; all **2,382** recorded System-1 decisions (226 gate + 2,156 loop) have `fallback_used=false`. There are **9 probe errors**, all downstream Stage-2 summarizer failures rather than sidecar fallback events. Thus “zero fallback” describes routing reliability, not error-free compaction. The sidecar chose `compact` on 226/226 gate probes. Of the 226 compaction events, **223** have `decision_source=system1_gate_system2_summarizer` and **3** have `decision_source=system2_defer`; **217** produced persisted compacted states, while **9** recorded `probe_error` skips. The three uncertainty deferrals occur at `ic_bash_fs2_039` iteration 10 (p=0.7805), `swe_django__django-12470` iteration 55 (p=0.8249), and `swe_django__django-12700` iteration 83 (p=0.7274), each below the **0.839384** risk threshold. The Stage-2 result still compacted each of them. This verifies that the defer path works, though it has not diversified final actions.

**Context reduction for long tasks.** With `compaction_interval_iterations=10` and a retained tail, successful compacted boundaries commonly advance by nine iterations (9, 18, 27, …). Across the **217** successful compactions, median full probe input is **30,575 bytes**, median compacted output is **5,879 bytes**, and median per-event output/input ratio is **19.4%**. These are probe/summary byte counts, not measured model context tokens. [`10924`](heldout/batch_heldout_100_system1/swe_django__django-10924.json) moves from 20,926→4,312 bytes on its first compaction and reaches boundary 126 after 14 states; [`14017`](heldout/batch_heldout_100_system1/swe_django__django-14017.json) moves from 25,513→3,304 bytes on its first. [`ic_ctf_014`](heldout/batch_heldout_100_system1/ic_ctf_014.json) condenses 16,979→2,960 bytes around the discovery of the nested file and later finds the flag. [`frames_043`](heldout/batch_heldout_100_system1/frames_043.json) condenses a very large 72,745-byte input to 2,549 bytes. The successful [`frames_001`](heldout/batch_heldout_100_system1/frames_001.json), [`frames_036`](heldout/batch_heldout_100_system1/frames_036.json), and [`ic_ctf_060`](heldout/batch_heldout_100_system1/ic_ctf_060.json) need no compaction; their gains cannot be credited to it. The implementation's Stage-2 prompt explicitly says the gate has already approved compaction and asks only for a grounded state; it does not ask Stage-2 to re-decide, except on the uncertainty defer path ([`compaction.go`](../../internal/fsm/compaction.go)).

## Where the decision model and Go control plane fell short

**The gate is saturated.** `P(compact)` ranges **0.7274–0.9986**, median **0.9668**, mean **0.9575**; its 10th and 90th percentiles are approximately **0.9130** and **0.9929**. Every calibrated argmax is `compact`, so there are **zero `system1_skip`** events. Only three low-confidence calls defer to System-2, and all three still compact. **220/226 (97.3%)** compaction probe renderings set `truncated=true`; the Go renderer caps individual goals, prior state, step arguments and outputs, and final prompt at **32 KiB**, then the sidecar uses a **4,096-token** sequence budget ([`systemone_state.go`](../../internal/fsm/systemone_state.go)). The truncation flag does not prove which information was omitted or that truncation caused saturation. It does mean the gate mostly decides on clipped evidence, and no observed case demonstrates learned skipping. At an interval of ten iterations, there may be legitimate reasons to compact frequently, but 100% approval makes the gate's selectivity unproven.

**Stage-2 schema and deadline failures.** The **9** `probe_error` events are: two `context deadline exceeded` on [`ic_ctf_069`](heldout/batch_heldout_100_system1/ic_ctf_069.json) at iterations 8–9; six JSON type failures on `verified_findings[0]` at [`ic_ctf_070`](heldout/batch_heldout_100_system1/ic_ctf_070.json) iteration 28, [`12470`](heldout/batch_heldout_100_system1/swe_django__django-12470.json) iteration 91, [`12589`](heldout/batch_heldout_100_system1/swe_django__django-12589.json) iteration 82, [`12700`](heldout/batch_heldout_100_system1/swe_django__django-12700.json) iteration 55, [`13033`](heldout/batch_heldout_100_system1/swe_django__django-13033.json) iteration 64, and [`13265`](heldout/batch_heldout_100_system1/swe_django__django-13265.json) iteration 64; and one malformed array (`invalid character '}' after array element`) on [`13964`](heldout/batch_heldout_100_system1/swe_django__django-13964.json) iteration 55. Several raw previews use the older `should_compact`/`reason`/`state` envelope; that envelope alone is valid under the current Stage-2 prompt. The failure is specifically string elements where `verified_findings` requires `{summary, source_step_ids}` objects, or malformed JSON. The FSM records a skip rather than persisting an invalid state; later probes recover on many runs. The current parser accepts flexible string slices for several fields but not strings for `VerifiedFinding` ([`compaction.go`](../../internal/fsm/compaction.go)).

**Loop guard: one harmful intervention, little help on semantic loops.** The sidecar returns `none` on **2,154/2,156 (99.91%)** loop probes. Its maximum `P(intercept)` over all probes is **0.1315**; its only non-`none` predictions are the two `force_synthesis` calls on `ic_ctf_003` described above. The first is downgraded to `intercept`; the second forces synthesis after the blocked step establishes a strike. Both heuristic verdicts were `none`. The deterministic hybrid backstop only fires at **≥5 consecutive identical calls with unchanged outputs**, so changing query strings or command arguments evade it ([`loop_guard.go`](../../internal/fsm/loop_guard.go)). **2,080/2,156 (96.5%)** loop probe renderings are marked truncated; the renderer keeps at most **12** recent steps and clips arguments/outputs, so broader semantic repetition is difficult to see. This is a plausible mechanism, not proof that truncation alone explains the low intervention rate.

The long failures show the difference between syntactic and semantic repetition. [`ic_ctf_070`](heldout/batch_heldout_100_system1/ic_ctf_070.json) reaches the 3,600 s limit with **174** tool steps and repeatedly searches the extracted filesystem/history for a flag without one. [`swe_django__django-12470`](heldout/batch_heldout_100_system1/swe_django__django-12470.json) reaches 129 steps, repeatedly revisiting ordering methods and generating no patch; [`12589`](heldout/batch_heldout_100_system1/swe_django__django-12589.json) reaches 125 steps while re-reading `Subquery`/`GROUP BY` code, also without a patch; [`13265`](heldout/batch_heldout_100_system1/swe_django__django-13265.json) reaches 141 steps of migration `_order`/`AddIndex` searches without a patch. Their commands are similar in purpose but rarely byte-identical. The guard reports no intervention, and all reach the wall-clock limit. There are **13** tasks at roughly 3,600 s in the new run; timeout alone does not imply failure—`10924` still produces a Docker-resolved patch.

**Latency is material.** Sum of all 100 task durations is **72,376 s (20.10 h)**. The CPU sidecar spends **1,706 s** on compaction gates and **16,122 s** on loop probes, totaling **17,829 s (4.95 h, 24.6%)** of task wall time. Stage-2 summarization adds **22,904 s (6.36 h)**; gate + loop + summarizer together account for **40,733 s (11.31 h, 56.3%)** if recorded component latencies are additive. These are sums of within-task telemetry, not an experimentally measured speedup if removed; task behavior and downstream LLM calls could change. Even so, probing the loop guard on nearly every tool call is expensive relative to its one applied intervention.

## Prioritized next iteration

1. **Fix destructive loop decisions first.** Require objective evidence of stalled progress before `force_synthesis`: a blocked *identical* command with unchanged output, or repeated goal-level state with no new artifacts. Keep the first sidecar-only strike as an advisory notice, preserve a path to run the pending command, and add a regression trace for `ic_ctf_003` that must reach the whitespace decoder. Log candidate command signatures, strike cause, and blocked observation together.
2. **Measure and train compaction selectivity.** Evaluate the gate on positive and negative probes at interval ten, including probes where a recent compaction already preserved all needed state. Report precision, recall, calibration, skip rate, and success/latency tradeoff. Do a shadow run with a skip-capable policy before applying it; today all 226 approvals leave no evidence that the gate adds value over unconditional compaction.
3. **Make Stage-2 output contract resilient.** Keep JSON schema constrained at generation if supported; otherwise normalize `verified_findings` strings into sourced finding objects only when provenance can be established, reject unsupported claims, and retry malformed JSON once within a bounded time budget. Distinguish model timeout, invalid JSON, and type mismatch in telemetry. Add regression fixtures for all seven observed parse failures and the two `ic_ctf_069` deadlines.
4. **Detect semantic stalls without suppressing progress.** Track repeated inspected file/function targets, repeated search intents, new test outcomes, code edits, and produced artifacts over a multi-compaction window. Trigger an advisory “choose a new experiment or finalize” when investigations recur with no new evidence. Test against `ic_ctf_070`, `12470`, `12589`, `13265`, and a progressing counterexample (`10924`). The five-identical-call backstop should remain as a deterministic safeguard.
5. **Reduce controller cost.** Profile CPU inference and cache or batch loop probes; invoke them after failed/repeated calls or stalled windows instead of every call if shadow evaluation confirms recall. Keep compaction interval ten initially and measure p50/p95 controller latency, task iterations, and resolution at fixed wall-clock limits. For SWE, add a patch-size and targeted-test checkpoint: `10924` resolves in Docker but changes 2,416 lines, while `11422` and `13033` regress despite local syntax/diff checks.
6. **Separate grader sensitivity from agent defects.** Make FRAMES equivalence explicit for semantically correct paraphrases and units (`006`, `090`), and adjudicate year-only versus completed-age questions (`033`, `036`). Preserve strict exact-match and Docker scores alongside adjudicated scores so future controller comparisons are not driven by formatting or ambiguity.

## Reproducibility and limits

Counts above were recomputed from task summaries and per-task `trajectory.events`, `steps`, and `compactions`; task links expose the exact commands, outputs, decision probabilities, errors, and final answers. The 19 `.patch` artifacts and 100 `.db` snapshots are present in the new batch; Docker grades are taken from the stored evaluation fields. The two benchmark runs are separate sampled trajectories with different elapsed budgets across baseline retry batches, so changed task grades do not identify a unique causal contribution from System-1. In particular, the short FRAMES and Base64 CTF gains occurred without compaction, and several apparent losses are exact-match or time-granularity effects. A paired, fixed-budget ablation using identical seeds and the same final Docker grading would be needed to estimate net controller benefit.
