# Bob Evaluation & Trajectory Dataset Specification

This document specifies the dataset architecture, partitioning, schemas, and usage for Bob's autonomous agent benchmark and training trajectories.

---

## 1. Overview & Partition Architecture

The dataset is partitioned into two strictly isolated sets with **zero task overlap**:

1. **Held-Out Evaluation Suite (`eval/tasks/heldout/`):**
   - 100 frozen tasks used exclusively for offline evaluation and capability benchmarking.
   - Guaranteed zero snooping: no training, fine-tuning, or prompt optimization uses these tasks.
2. **Training Trajectory Dataset (`eval/tasks/train/` & `eval/results/train/`):**
   - 417 clean tasks spanning the same 4 benchmark domains.
   - Multi-turn execution traces collected with `gemini-3.5-flash-lite` for Phase 4 Jev decision model experiments.
   - Full recording of all step-level tool invocations, stdout/stderr outputs, and SelfCompact compaction events.

```
eval/
├── tasks/
│   ├── heldout/                       # 100-task frozen evaluation suite
│   │   ├── heldout_100.json           # Primary 100-task benchmark manifest
│   │   ├── timeouts_44.json           # 44-task subset with 1-hour timeouts
│   │   └── swe_failed_iterations_17.json # 17-task SWE-bench high-iteration subset
│   └── train/                         # Clean training task pool
│       ├── train_pool.json            # 417 clean tasks (0% overlap with held-out)
│       ├── train_20.json              # 20-task small training baseline
│       └── train_sample_5.json        # 5-task smoke validation set
└── results/
    ├── heldout/                       # Evaluation rollouts on held-out tasks
    │   ├── heldout_100/               # Baseline rollouts (local Qwen3.6-35B-A3B-MTP-GGUF)
    │   ├── timeouts_44/               # Extended 1h timeout rollouts
    │   └── swe_iterations_17/         # 500-iteration SWE-bench rollouts
    └── train/                         # Training trajectories for distillation / Jev
        ├── batch_train_pool_1794581821/ # 417 rollouts, 19,706 steps, 2,004 compactions
        └── batch_train_sample_5_1794573538/ # Initial 5-task sample batch
```

## 2. Benchmark Domains & Distribution

Both splits draw from four standard benchmark suites representing diverse autonomous agent problem classes:

| Benchmark | Held-Out Count | Train Pool Count | Total Pool | Problem Class & Execution Environment | Metric & Verification |
| :--- | :---: | :---: | :---: | :--- | :--- |
| **DeepMind FRAMES** | 35 | 65 | 100 | Multi-hop reasoning, live web retrieval, tabular analysis, and temporal QA. Network enabled with Tavily search. | Exact normalized match against gold answer strings. |
| **InterCode-Bash** | 20 | 198 | 218 | Linux shell administration, file hierarchy search, stream editing, and text processing in Bubblewrap. | Filesystem directory and file hash tree match against oracle or gold command. |
| **InterCode-CTF** | 20 | 79 | 99 | Binary reverse-engineering, cryptographic decoding, and Python exploit scripting. | Capture of standard CTF flag format (`picoCTF{...}`) in agent stdout. |
| **SWE-bench Lite** | 25 | 75 | 100 | Real-world bug fixes in open-source Python repositories (`django/django`, `astropy/astropy`). | Candidate `git diff` patch verified inside official SWE-bench Docker containers. |
| **Total Tasks** | **100** | **417** | **517** | | |

> [!IMPORTANT]
> The training pool originally contained 7 tasks overlapping with `heldout_100.json`. These tasks were programmatically purged, ensuring a **strict 0% overlap guarantee** across task IDs and challenge instances.

## 3. Training Trajectory Dataset (`batch_train_pool_1794581821`)

The training rollout batch was generated by executing Bob with `gemini-3.5-flash-lite` across all 417 clean training tasks under `--timeout 3600` (1 hour) and `--max-iterations 500`.

### Key Metrics

| Metric | Value | Details |
| :--- | :--- | :--- |
| **Total Tasks** | **417 / 417 (100%)** | All tasks executed to completion or iteration cap |
| **Recorded Interaction Steps** | **19,706 steps** | Dense turn-by-turn state and tool execution traces |
| **SelfCompact Compactions** | **2,004 compactions** | Checkpointed state representations across 152 long-horizon tasks |
| **SQLite State DB Snapshots** | **417 databases** | Full FSM state machine transitions and provenance records |
| **Candidate Patches Generated** | **48 / 75 (64.0%)** | SWE-bench unified diff patches |
| **Graded Pass Rate** | **120 / 371 (32.3%)** | Graded subset across FRAMES, Bash, and CTF |

## 4. Schemas & Data Formats

### 4.1. Task Manifest Schema (`eval/tasks/**/*.json`)

Each task manifest is stored as a JSON object containing metadata and an array of task definitions:

```json
{
  "manifest_version": "1.0",
  "total_tasks": 417,
  "description": "Training task pool for trajectory generation",
  "tasks": [
    {
      "task_id": "swe_astropy__astropy-12907",
      "benchmark": "swe-bench-lite",
      "repo": "astropy/astropy",
      "base_commit": "d16bfe05a744909de4b27f5875fe0d4ed41ce607",
      "instruction": "Fix the following issue in astropy/astropy:\n\nModeling's `separability_matrix` does not compute...",
      "eval_type": "pytest_patch",
      "fail_to_pass": "[\"astropy/modeling/tests/test_separable.py::test_separable[compound_model6-result6]\"]",
      "pass_to_pass": "[\"astropy/modeling/tests/test_separable.py::test_coord_matrix\"]",
      "test_patch": "diff --git a/astropy/modeling/tests/test_separable.py ..."
    }
  ]
}
```

## 5. Version Control & Isolation Guidelines

To keep the repository lightweight and prevent accidental data leakage:

1. **Git Exclusions (`.gitignore`):**
   - Task manifests: `eval/tasks/**/*.json`
   - Rollout traces: `eval/results/**/*.json`
   - Candidate patches: `eval/results/**/*.patch`
   - Result directories: `eval/results/heldout/`, `eval/results/train/`, `eval/results/batch_*`
2. **Ephemeral Sandboxing:**
   - Every task executes inside an ephemeral `bwrap` container.
   - Host databases (`~/.local/share/bob/`) are never touched; runs use `/tmp/bob-eval-runs/`.
   - Bare Git mirrors (`scratch/eval_harness/repos/`) are shared read-only across tasks using temporary worktrees.

## 6. Inspecting the Dataset with Python

To load and analyze rollouts programmatically:

```python
import json
from pathlib import Path

batch_dir = Path("eval/results/train/batch_train_pool_1794581821")

# Load summary
with open(batch_dir / "summary.json") as f:
    summary = json.load(f)
print(f"Total tasks: {summary['total_tasks']}, Pass rate: {summary['graded_pass_rate']:.1%}")

# Iterate over task rollouts
for rollout_file in batch_dir.glob("*.json"):
    if rollout_file.name == "summary.json":
        continue
    with open(rollout_file) as f:
        data = json.load(f)
    
    task_id = data["task_id"]
    benchmark = data["benchmark"]
    steps = data["trajectory"]["steps"]
    compactions = data["trajectory"]["compactions"]
    print(f"Task: {task_id:<30} Benchmark: {benchmark:<15} Steps: {len(steps):<4} Compactions: {len(compactions)}")
```
